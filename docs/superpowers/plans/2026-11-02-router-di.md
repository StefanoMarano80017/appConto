# Router, iniezione delle dipendenze e test — piano di implementazione

> **Per chi esegue:** SOTTO-SKILL OBBLIGATORIA: superpowers:subagent-driven-development (consigliata) o superpowers:executing-plans, un task alla volta. I passi usano le caselle (`- [ ]`).

**Obiettivo:** nessun modulo apre il DB all'import; repository, servizi e router si costruiscono con factory collegate in un'unica radice di composizione; contratti HTTP fissati prima del cambio; test con finti per router e servizi; poi il refactoring dei router.

**Architettura:** strada B del design. I contratti HTTP (fase 1) passano da un aiutante il cui interno cambia in fase 2, mentre i file di test no. La fase 2 procede "a strangolamento": ogni livello diventa factory e, finché i chiamanti non sono migrati, il vecchio singleton resta come **istanza legacy** costruita dalla factory (marcata `// LEGACY: rimossa in T2.8`). L'ultimo task della fase rimuove le istanze legacy e lo shim di `db/client.ts`.

**Stack:** Node 24, TypeScript, Express 5, better-sqlite3 + Drizzle, zod, `node:test` + `assert/strict` + `mock` di `node:test`, `tsx`.

**Spec:** `docs/superpowers/specs/2026-11-02-router-di-design.md`; riferimento dei codici `A-…`: `docs/superpowers/specs/2026-11-02-router-analysis.md`.

## Focus di revisione

1. **Due `Database` nello stesso processo** (test): oggi lo stato `closed` è globale di modulo. Atteso: istanze indipendenti, chiusura dell'una senza effetti sull'altra. → test in T2.1.
2. **Ripristino differito che fallisce all'avvio**: stesso log e stesso exit code di oggi. → criterio "test runtime invariati" in T2.7.
3. **Arresto prima che il DB sia aperto** (segnale durante il bootstrap): la chiusura non deve lanciare. → test in T2.7.
4. **Cicli di import che, tolti i singleton, lasciano `undefined` a runtime** (ESM, ordine di valutazione). → sonda in T2.8 che importa ogni modulo non di test.
5. **Aiutante HTTP che lascia server o DB aperti** fra un test e l'altro: `close()` idempotente. → test in T1.1.
